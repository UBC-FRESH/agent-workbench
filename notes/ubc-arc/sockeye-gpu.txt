Submitting GPU Jobs
Submitting jobs from directories residing in /arc/home is not allowed. Transfer your job script to a directory in /scratch FS and submit the job from there.

GPU Jobs
This GPU Slurm script begins with setting up job-specific parameters, such as the job name, queue or partition selection, and the desired resources. These resources include a single compute node, 12 CPU cores, 2 GPUs, 64GB memory, and a maximum runtime of 72 hours. The script also configures email notifications for job start, end, or errors, sending notifications to an email address. In the following example, the --gpus=2 directive requests 2 GPUs for the job.



#!/bin/bash

#SBATCH --job-name=jobname            
#SBATCH --account=<alloc-code>-gpu    
#SBATCH --nodes=1                   
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=12                            
#SBATCH --mem=64G                   
#SBATCH --time=72:00:00              
#SBATCH --gpus=2
#SBATCH --output=output.txt          
#SBATCH --error=error.txt           
#SBATCH --mail-user=<your-email>
#SBATCH --mail-type=ALL                                

module load gcc
module load cuda
module load <software_package_1>
module load <software_package_2>

cd $SLURM_SUBMIT_DIR

export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
<gpu_executable>
To specifically request a 32GB VRAM GPU node, use the following feature flag: --constraint=gpu_mem_32

MPI GPU Jobs
The Slurm directives requests resources for an MPI GPU job, including 2 nodes, 24 CPU cores per node, 24 MPI processes, 4 GPUs, 186GB of RAM per node, and a maximum runtime of 96 hours. It executes the MPI GPU program using mpiexec.



#!/bin/bash

#SBATCH --job-name=jobname        
#SBATCH --account=<alloc-code>-gpu
#SBATCH --nodes=2                                
#SBATCH --ntasks-per-node=1
#SBATCH --ncpus-per-task=24
#SBATCH --mem=186G                  
#SBATCH --time=96:00:00              
#SBATCH --gpus-per-node=4
#SBATCH --output=output.txt          
#SBATCH --error=error.txt            
#SBATCH --mail-user=<your-email> 
#SBATCH --mail-type=ALL                

module load gcc                
module load openmpi         
module load cuda              
module load <software_package_1> 

cd $SLURM_SUBMIT_DIR  

export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
mpiexec --np 2 <mpi_gpu_executable>  
In this example, the --gpus-per-node=4 directive explicitly requests 4 GPUs for the MPI GPU job

Interactive GPU
While batch submissions are generally the most efficient method for fully utilizing computational resources, Sockeye also supports interactive job submissions, making it a valuable option for tasks such as

RAM intensive graphical applications like MATLAB
Interactive "console tools" like R
Significant software development and compiling efforts
A Slurm interactive session reserves resources on compute nodes allowing you to use them interactively as you would the login node. There are two main commands that can be used to make a session, srun and salloc.

Once an interactive session starts, it will use the entire requested block of CPU time and other resources even if they remain unused, until explicitly terminated. So don't forget to exit the interactive session once finished. Additionally, if the session exceeds the maximum walltime of 24 hours, it will be automatically terminated. The --constraint=gpu_mem_32 flag is not supported for interactive jobs.

Using srun
srun will add your resource request to the queue. When the allocation starts, a new bash session will start up on one of the granted nodes.



$ srun --account=<st-alloc-1>-gpu --partition=interactive_gpu --time=1:0:0 -N 1 -n 2 --mem=8G --gpus=1 --pty /bin/bash

When the job starts, the hostname in the prompt will change in compute node (ie. se060).

Using salloc
salloc functions similarly srun --pty bash in that it will add your resource request to the queue. 



salloc  --account=<st-alloc-1>-gpu --partition=interactive_gpu --time=1:0:0 -N 1 -n 2 --mem=8G --gpus=1 
And when the job starts, you will a message similar below and the hostname in the prompt will change in compute node (ie. se060).



salloc: Granted job allocation 570
salloc: Waiting for resource configuration
salloc: Nodes se064 are ready for job
You can run a simple script that simplifies the process of initiating an interactive GPU job. It allows you to create and execute the script, eliminating the need to recall or manually type the command each time you want to start an interactive GPU job.



# To create a script for easier GPU job initiation, follow these steps:

# 1. Navigate to your scratch directory

# 2. Create the script file using preferred text editor.
$ vi interactive_gpu.sh

# 3. Add the following lines to the script:
#!/bin/bash
srun --account=<st-alloc-1>-gpu --partition=interactive_gpu --time=1:0:0 -N 1 -n 2 --mem=8G --gpus=1 --pty /bin/bash
# If you prefer, you can use 'salloc' instead of 'srun'.

# 4. Save and exit the text editor.

# 5. Make the script executable
$ chmod u+x interactive_gpu.sh

# 6. Run the script to start an interactive GPU job
$ ./interactive_gpu.sh


Graphical Interactive
To use X11 in an interactive shell, first ssh into the login node from your local machine with the -X or -Y flag:



ssh -Y cwl@sockeye.arc.ubc.ca
Submit an interactive job with X11 forwarding enabled using --x11 option.



$ srun --x11 --account=<st-alloc-1>-gpu --partition=interactive_gpu --time=1:0:0 -N 1 -n 2 --mem=8G --gpus=1 --pty /bin/bash
Using nvidia-smi
You can obtain basic information on the NVIDIA GPU and its current usage such as GPU and memory utilization, power consumption, running processes, etc. using the command nvidia-smi.  Check out its man page for more details: man nvidia-smi.

You must be logged into the GPU node where your job is running.
1. Submit job



$ sbatch gpu-jobs.sh    # You can find the example of "gpu-jobs.sh" in the next section of this page.
2. Query which node your job is running on



$ squeue -n $JOBID -u $USER
3. SSH into that gpu node



$ ssh <node>   # Example: ssh se066
4. Run nvidia-smi. The output should look similar to the following

Identifying the assigned GPUs for your job
Your running GPU job should be getting exclusive access to the number of requested GPUs. You can only use GPUs assigned to your job. Attempting to use GPUs not assigned to your job will fail.

If you need to identify the GPUs available to your job, you can do so by using the command below:

1. For Interactive GPU job:

1) Identify the UUID of the GPU assigned to your job.



$ nvidia-smi --query-gpu=uuid --format=csv,noheader
GPU-c892056f-9710-192e-1b4f-73a1da8263e7 
 
$ nvidia-smi -L | grep "GPU-c892056f-9710-192e-1b4f-73a1da8263e7"
GPU 2: Tesla V100-SXM2-16GB (UUID: GPU-c892056f-9710-192e-1b4f-73a1da8263e7)
 
2) Display the status of the specific GPU by providing the UUID



$ nvidia-smi -i <UUID>


2. For batch GPU job:

The environment variable CUDA_VISIBLE_DEVICES will not work in your shell if you SSH to the node separately from the job. The SSH connection has no knowledge of your job or its environment. However you can access the environment variable from a job script. See the example below:

Sample GPU Job script


#!/bin/bash
 
#SBATCH --time=3:00:00                  # Requested walltime
#SBATCH --nodes=1                       # Number of nodes
#SBATCH --ntasks=1                      # Number of tasks (MPI processes)
#SBATCH --cpus-per-task=8               # Number of CPU cores per task
#SBATCH --gpus-per-node=1               # Number of GPUs per node
#SBATCH --mem=16GB                      # Requested memory
#SBATCH --job-name=my_job               # Job name
#SBATCH --account=alloc-code-gpu        # Account allocation code 
#SBATCH --mail-user=<your-email>    # Your email address for notifications
#SBATCH --mail-type=ALL                 #
#SBATCH --output=/path/to/output.txt    # Output file
#SBATCH --error=/path/to/error.txt      # Error file
 
################################################################################

cd $SLURM_SUBMIT_DIR
module load <package>

nvidia-smi nvidia-smi --query-gpu=uuid --format=csv,noheader > my_current_GPU_UUID.txt > /scratch/path/to/my_current_GPU_UUID.txt
 
export OMP_NUM_THREADS=8

<gpu_executable>
After submitting your job via sbatch, the "my_current_GPU_UUID.txt"  file contains the GPU information and UUID as shown by the output of nvidia-smi, and nvidia-smi --query-gpu=uuid --format=csv,noheader > my_current_GPU_UUID.txt above.

Once you get the UUID, you can specify what information you would like to see by using the nvidia-smi command with  '-q' (query) and '-d' (display) flags when the job is running to monitor how your job is utilizing the GPU resources.



$ nvidia-smi -q -d MEMORY,UTILIZATION -i GPU-c892056f-9710-192e-1b4f-73a1da8263e7
